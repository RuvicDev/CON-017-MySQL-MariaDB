1. ¿Qué es y para qué sirve?1. What is it and what is it for?

El conector MySQL / MariaDB permite que el agente de Ruvic acceda a tu base de datos en modo solo lectura: puede consultar información, pero nunca modificarla. Una vez configurado, puedes pedirle al agente cosas como:

  • “Genera un reporte con las ventas del último trimestre y envíalo por correo.”
  • “¿Cuántos clientes nuevos se registraron esta semana?”
  • “Revisa por qué este query está lento y proponme mejoras.”

Operaciones soportadas:

The MySQL / MariaDB connector lets the Ruvic agent access your database in read-only mode: it can query information but never modify it. Once configured, you can ask the agent things like:

  • “Build a report with last quarter's sales and email it.”
  • “How many new customers signed up this week?”
  • “Check why this query is slow and suggest improvements.”

Supported operations:

OperaciónOperation Qué haceWhat it does
db.list_tables Lista las tablas de la base de datos con su cantidad de filasLists the database tables with their row counts
db.read Lee los datos de una tabla (con límite de filas)Reads data from a table (with a row limit)
db.stats Estadísticas de una tabla: filas, tamaño, columnas y tiposTable statistics: rows, size, columns and types
db.explain Analiza el plan de ejecución de una consulta sin ejecutarlaAnalyzes a query's execution plan without running it
Solo lectura, por diseñoRead-only by design El conector abre cada sesión con SET SESSION TRANSACTION READ ONLY y el usuario dedicado solo tiene permiso SELECT. Aunque el agente lo intentara, el servidor rechazaría cualquier escritura. The connector opens every session with SET SESSION TRANSACTION READ ONLY and the dedicated user only has SELECT. Even if the agent tried, the server would reject any write.

2. Prerrequisitos2. Prerequisites

  • Una base de datos MySQL 5.7+ / MariaDB 10.2+ (en tu servidor, en la nube — RDS, Cloud SQL, Azure Database for MySQL — o en Docker).
  • Acceso administrativo a la base de datos (rol con permiso para crear usuarios), solo durante la configuración inicial.
  • Acceso de red desde la plataforma Ruvic al servidor de base de datos (host y puerto alcanzables; regla de firewall o lista de IPs permitidas si aplica).
  • Los datos de conexión: host, puerto (por defecto 3306) y nombre de la base de datos.
  • A MySQL 5.7+ / MariaDB 10.2+ database (self-hosted, cloud — RDS, Cloud SQL, Azure Database for MySQL — or Docker).
  • Administrative access to the database (a role that can create users), only during initial setup.
  • Network access from the Ruvic platform to the database server (reachable host and port; firewall rule or IP allow-list if applicable).
  • The connection details: host, port (default 3306) and database name.

3. Configuración en el fabricante (paso a paso)3. Vendor-side setup (step by step)

Vas a crear un usuario dedicado de solo lectura para Ruvic. No uses un usuario administrador (root) ni el de tu aplicación: un usuario dedicado permite auditar la actividad del agente y limitar el acceso al mínimo.

You will create a dedicated read-only user for Ruvic. Do not reuse an admin user (root) or an application user: a dedicated user lets you audit the agent's activity and keep access to a minimum.

  1. Conéctate a la base de datos como administrador.

    Usa mysql u otra herramienta (MySQL Workbench, DBeaver, phpMyAdmin) con un rol administrador:

    Connect to the database as an administrator.

    Use mysql or another tool (MySQL Workbench, DBeaver, phpMyAdmin) with an admin role:

    mysql -h TU_HOST -P 3306 -u root -p TU_BASE_DE_DATOS
  2. Crea el usuario de solo lectura para Ruvic.

    Elige una contraseña fuerte (mínimo 16 caracteres, generada aleatoriamente) y guárdala: la usarás en el formulario de Ruvic (campo Contraseña). Reemplaza % por la IP de la plataforma Ruvic si tu servidor la conoce de antemano:

    Create the read-only user for Ruvic.

    Choose a strong password (16+ random characters) and save it: you will paste it into the Ruvic form (Password field). Replace % with the Ruvic platform IP if you know it in advance:

    CREATE USER 'ruvic_reader'@'%' IDENTIFIED BY 'CAMBIA_ESTA_CONTRASEÑA';
  3. Otorga los permisos de lectura.

    Sobre la base de datos que quieras exponer al agente:

    Grant read permissions.

    On the database you want to expose to the agent:

    GRANT SELECT ON tu_base_de_datos.* TO 'ruvic_reader'@'%';
FLUSH PRIVILEGES;
    NotaNote GRANT SELECT ON basededatos.* aplica automáticamente a las tablas que se creen después, sin repetir el GRANT. GRANT SELECT ON database.* automatically covers tables created afterwards, without re-running the GRANT.
  4. Habilita el acceso de red desde Ruvic.

    Si tu MySQL/MariaDB restringe conexiones por IP (habitual en producción), permite la IP de la plataforma Ruvic:

    • Servidor propio: crea el usuario con el host exacto en vez de % (ej. CREATE USER 'ruvic_reader'@'IP_DE_RUVIC' ...) y verifica que bind-address en my.cnf permita conexiones remotas.
    • AWS RDS / Cloud SQL / Azure: agrega la IP en el security group o en la lista de redes autorizadas de la consola del proveedor.
    Enable network access from Ruvic.

    If your MySQL/MariaDB restricts connections by IP (common in production), allow the Ruvic platform IP:

    • Self-hosted: create the user with the exact host instead of % (e.g. CREATE USER 'ruvic_reader'@'RUVIC_IP' ...) and make sure bind-address in my.cnf allows remote connections.
    • AWS RDS / Cloud SQL / Azure: add the IP to the security group or authorized networks list in the provider console.
    [ Captura: regla de firewall / security group con la IP de Ruvic — reemplazar por assets/img/mysql-firewall.png ] [ Screenshot: firewall rule / security group with the Ruvic IP — replace with assets/img/mysql-firewall.png ]
  5. Verifica el usuario desde fuera del servidor.

    Desde una máquina distinta al servidor de BD (idealmente con salida de red similar a la de Ruvic):

    Verify the user from outside the server.

    From a machine other than the DB server (ideally with network egress similar to Ruvic's):

    mysql -h TU_HOST -P 3306 -u ruvic_reader -p tu_base_de_datos -e "SELECT 1"

    Si responde 1, el fabricante quedó listo. Anota estos valores para la siguiente sección: host, puerto, base de datos, usuario y contraseña.

    If it returns 1, the vendor side is ready. Write down these values for the next section: host, port, database, user and password.

4. Permisos requeridos4. Required permissions

Principio de mínimo privilegio: el usuario de Ruvic solo necesita estos permisos. No otorgues ALL PRIVILEGES, roles de superusuario, escritura ni administración.

Least-privilege principle: the Ruvic user only needs these permissions. Do not grant ALL PRIVILEGES, superuser, write or admin roles.

PermisoPermission Para qué lo usa el conectorWhy the connector needs it
SELECT (sobre la base de datos a consultar)(on the database to query) Leer datos (db.read), contar filas y calcular estadísticas (db.stats), planificar consultas (db.explain)Read data (db.read), count rows and compute statistics (db.stats), plan queries (db.explain)

Las vistas de catálogo que usa el conector (information_schema.tables, information_schema.columns) están disponibles para cualquier usuario autenticado sobre sus objetos visibles; no requieren permisos adicionales.

The catalog views the connector uses (information_schema.tables, information_schema.columns) are available to any authenticated user over their visible objects; no extra permissions required.

6. Verificación6. Verification

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: “Conexión exitosa a tu-host:3306/tu_base”. La tarjeta del conector cambia a estado Configurado.

    Successful connection test.

    The Test connection button should return: “Successful connection to your-host:3306/your_db”. The connector card switches to Configured.

  2. Automatización mínima de prueba.

    Abre una conversación nueva con el agente y pídele:

    “Lista las tablas de la base de datos MySQL y dime cuántas filas tiene cada una.”

    El agente debe responder con el listado real de tus tablas. Si lo hace, el conector quedó operativo de punta a punta.

    Minimal test automation.

    Open a new conversation with the agent and ask:

    “List the tables in the MySQL database and tell me how many rows each one has.”

    The agent should reply with your actual table list. If it does, the connector is fully operational.

8. Preguntas frecuentes y notas de seguridad8. FAQ and security notes

¿El agente puede modificar o borrar datos?Can the agent modify or delete data?

No. El conector abre cada sesión en modo READ ONLY y el usuario ruvic_reader solo tiene permiso SELECT. Hay dos barreras independientes.

No. The connector opens every session in READ ONLY mode and the ruvic_reader user only has SELECT. Two independent safeguards.

¿Dónde queda guardada la contraseña?Where is the password stored?

Como secreto en el almacén de credenciales de la plataforma, asociado a tu usuario. La interfaz nunca vuelve a mostrarla; solo indica “definida”. Para cambiarla, escribe una nueva en el formulario; para conservarla al editar otros campos, deja el campo vacío.

As a secret in the platform's credential store, tied to your user. The UI never displays it again; it only shows “set”. To change it, type a new one in the form; to keep it while editing other fields, leave the field empty.

Rotación de credencialesCredential rotation

Recomendado cada 90 días o según tu política: cambia la contraseña en MySQL/MariaDB (ALTER USER 'ruvic_reader'@'%' IDENTIFIED BY '...';), actualízala en el formulario del conector y pulsa Probar conexión.

Recommended every 90 days or per your policy: change the password in MySQL/MariaDB (ALTER USER 'ruvic_reader'@'%' IDENTIFIED BY '...';), update it in the connector form and click Test connection.

¿Qué hago si la contraseña se compromete?What if the password is compromised?

  1. Cambia la contraseña en MySQL/MariaDB de inmediato (ALTER USER ... IDENTIFIED BY ...) o bloquea el usuario (ALTER USER 'ruvic_reader'@'%' ACCOUNT LOCK;).
  2. Revisa la actividad reciente del usuario en los logs del servidor.
  3. Actualiza la nueva contraseña en el formulario del conector.
  1. Change the password in MySQL/MariaDB immediately (ALTER USER ... IDENTIFIED BY ...) or lock the user (ALTER USER 'ruvic_reader'@'%' ACCOUNT LOCK;).
  2. Review the user's recent activity in the server logs.
  3. Update the new password in the connector form.

¿Expiran las credenciales?Do the credentials expire?

Por defecto no (usuario/contraseña de MySQL/MariaDB no caducan solos). Si tu política exige expiración, configúrala con PASSWORD EXPIRE INTERVAL N DAY al crear o alterar el usuario y programa la rotación antes de esa fecha.

By default no (MySQL/MariaDB user/password does not expire on its own). If your policy requires expiration, set it with PASSWORD EXPIRE INTERVAL N DAY when creating or altering the user and schedule rotation before that date.

Buenas prácticasBest practices Usa siempre un usuario dedicado y de solo lectura; restringe el acceso por IP en vez de '%' cuando sea posible; no expongas bases de datos con datos sensibles que el agente no necesite; y evita compartir la contraseña por canales no seguros. Always use a dedicated read-only user; restrict access by IP instead of '%' when possible; do not expose databases with sensitive data the agent doesn't need; and never share the password over insecure channels.
